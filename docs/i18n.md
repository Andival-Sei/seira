# Мультиязычность

## Базовое решение

Seira использует `i18next`, `react-i18next`, `i18next-browser-languagedetector` и `i18next-icu`.

Это оставляет проект в формате React + Vite без SSR, но сразу дает нормальную основу для большого приложения:

- автоматический выбор языка из настроек браузера;
- fallback на русский язык;
- ICU-сообщения для множественных чисел, вариантов и сложной грамматики;
- форматирование дат, чисел и валют через стандартный `Intl`;
- переводы отдельно от React-компонентов.

## Локали

На старте поддерживаются:

- `ru` - язык по умолчанию и fallback;
- `en` - английская локаль.

Если браузерный язык не входит в список поддерживаемых или не определяется, приложение использует `ru`.

## Где лежит код

```text
src/i18n/
  i18n.ts        # инициализация i18next и browser language detection
  locales.ts     # список поддерживаемых локалей и fallback
  resources.ts   # словари переводов
  format.ts      # общие Intl-хелперы для дат и чисел

src/features/i18n/
  LanguageSelect.tsx
```

## Правила разработки

- Не писать пользовательские строки напрямую в компонентах, если строка является частью интерфейса.
- Не склеивать фразы руками через шаблонные строки. Для вариантов, чисел и склонений использовать ICU.
- Даты, числа и валюты форматировать через `Intl`, а не через ручные строки.
- Технические идентификаторы вроде `Supabase Auth`, `Postgres RLS`, `TOTP` можно оставлять без перевода, если это название технологии или протокола.
- Новая фича должна добавлять ключи переводов одновременно с UI.

## Текущая стратегия URL

Приложение пока является закрытой SPA без публичного SEO-контура, поэтому локаль не вынесена в URL. Язык определяется из браузера, а ручной переключатель меняет язык в текущей сессии.

Если появятся публичные страницы, лендинги или shareable-ссылки с языковой семантикой, нужно перейти к локализованным маршрутам вида `/ru/...` и `/en/...`.
